# Verification

Run `npm ci && npm test`. The suite builds the actual implementation and covers:

- Reference FIFO/fair/aging results, quota/resource constraints, FIFO within groups, future arrivals, and all four fixture workloads under all three policies.
- A saturated 2:1 weighted workload, aging protection, cancellations, exact expiry, bounded inputs, and browser-engine parity.
- Durable idempotency, semantic arrival differences, correct-result verification, completion replay, token/heartbeat fencing, retry exhaustion, and snapshot secret omission.
- SQLite reopening and eight independent simultaneous claim processes competing for two slots.
- Actual authenticated HTTP submission, claims, renewal, completion, invalid/oversized input, safe static paths, and a real worker loop.
- An OS-process drill that SIGKILLs a worker and the queue server, restarts the same database, reassigns work, rejects the old completion, and checks final jobs/reservations.

`npm run evidence` produces JSON reference results and a fresh process-drill record in ignored `reports/`. The checked-in browser reference JSON is generated by the same policy. GitHub Actions runs tests and generated-output checks and starts a nonroot/read-only container against real HTTP requests.

These are synthetic local experiments, not production throughput, a security audit, a formal fairness proof, or an HPC/GPU integration certification. Record hosted run links after observing them.
